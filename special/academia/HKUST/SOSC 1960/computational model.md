# computational model

Write a program that does a task, and find a person who does it too. Run both and compare. The comparison is on behaviour, not anatomy.

A program that gets the same results as a person on a task is a working account of what that person is doing. Matching behaviour alone does not prove the two work in the same way, since a different program could reach the same results. And a model does not have to be right. One that gets the task wrong in a particular way still argues against any explanation that would be wrong in the same way.

A person cannot be taken apart, and one factor cannot be varied inside a participant while the rest are held still. In a model every factor is a parameter, so changing one gives an exact answer. Researchers infer an account of a process from a correlation between performance and whatever else changed with it. A person gives a number, and a model gives an explanation that comes apart piece by piece.

## reading a damaged model

Take a face-recognition model that performs as well as a person, and damage one component. Its performance drops on Asian faces and holds steady on Caucasian ones.

That asymmetry is a prediction about people. A person with damage in the corresponding place should show it, which locates the part both cases share. If people do show it, the account treating face recognition as one undifferentiated operation is wrong. If they do not, the model is wrong.

The damaged model predicted that result without a new participant, and a manipulation no brain could receive made the error visible. Diagnosing a process is what a model is best at.

The model's decomposition predicts one particular pattern, not that the brain uses that same decomposition. A model that splits the process into different parts could produce the same asymmetry. The comparison proves less than it first appears.
